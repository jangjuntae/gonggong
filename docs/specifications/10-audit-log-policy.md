# 감사로그 정책

## 기록 대상

- 개인정보 조회·검색·다운로드 및 변경
- 신청 상태 변경, 담당자 배정과 보완 요청
- 심사 결과 등록, 승인·거절
- 대출 실행, 상환·정정 등 금융거래 처리
- 상품·규칙·권한·보안 설정 변경
- 권한 거부, 반복 실패와 비정상 대량 조회

## 필수 필드

| 필드 | 설명 |
|---|---|
| 사용자 ID / 직원 ID | 인증 주체와 업무 직원 식별자 |
| 역할 / 부서 | 행위 당시 권한 스냅샷 |
| 행위 | 조회·생성·변경·승인 등 표준 코드 |
| 대상 리소스 / ID | 대상 유형과 내부 식별자 |
| 처리 시간 | 서버 기준 `TIMESTAMPTZ` |
| IP / User-Agent / traceId | 요청 추적 정보(TODO: 보관 범위) |
| 성공/실패 | 결과와 표준 실패 코드 |
| 변경 전/후 값 | 허용된 비민감 필드의 차이 |
| 변경 사유 | 업무상 사유 및 승인 참조 |

## 보호와 보관

- 비밀번호, 인증 토큰, 주민번호·계좌번호 원문, 증빙 원문은 기록하지 않는다.
- 민감 변경값은 마스킹·해시 또는 필드명과 변경 여부만 저장한다.
- 일반 애플리케이션 계정은 감사로그 UPDATE/DELETE 권한을 갖지 않는다.
- 로그 위변조 탐지, 별도 저장소 전송, 보존 기간과 파기 승인은 TODO이다.
- 감사로그 저장 실패 시 핵심 거래를 실패시킬지 Outbox로 보장할지는 유스케이스별 확정이 필요하다.

## 조회 정책

AUDITOR의 읽기 전용 접근을 기본으로 하고 조회 자체도 감사한다. 기간·대상·사유를 요구하며 대량 내보내기는 추가 승인과 워터마크를 검토한다.
