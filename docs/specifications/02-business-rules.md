# 업무 규칙

## BR-001 승인 신청의 대출 실행

조건: 신청 상태가 `APPROVED`이다.  
처리: 대출계약, 실행 원장, 상태, 상환계획과 감사로그를 한 트랜잭션으로 생성한다.  
위반 시: 요청을 거절하고 아무 데이터도 변경하지 않는다.  
DB 제약조건 적용 가능 여부: 부분 적용 가능(신청-대출 1:1 UNIQUE).  
애플리케이션 검증 필요 여부: 필요.

## BR-002 거절 신청 실행 금지

조건: 신청 상태가 `REJECTED`이다.  
처리: 대출 실행을 허용하지 않는다.  
위반 시: 업무 오류를 반환하고 보안상 필요한 경우 감사로그를 남긴다.  
DB 제약조건 적용 가능 여부: 상태 간 제약은 애플리케이션 또는 DB 트리거 검토.  
애플리케이션 검증 필요 여부: 필요.

## BR-003 상환계획 생성 조건

조건: 승인된 신청을 기반으로 대출 실행 중이다.  
처리: 실행 트랜잭션 안에서만 상환계획을 생성한다.  
위반 시: 전체 롤백한다.  
DB 제약조건 적용 가능 여부: FK 적용 가능.  
애플리케이션 검증 필요 여부: 필요.

## BR-005 동일 상품 중복신청

처리: 중복 여부를 원자적으로 확인한다. 활성 상태 범위와 재신청 유예기간은 TODO.

## BR-006 상품별 신청 한도

처리: 신청 접수 시 검증하고 적용 규칙 버전을 보존한다.  
위반 시: 미충족 조건을 반환한다.

애플리케이션 검증 필요 여부: 필요.

## BR-010 멱등 상환

조건: 상환 요청에 고객/요청 범위에서 유일한 Idempotency Key가 있다.  
처리: 최초 요청만 반영하고 동일 요청은 저장된 결과를 반환한다. 키가 같고 본문이 다르면 거절한다.  
위반 시: 충돌 응답을 반환한다.  
DB 제약조건 적용 가능 여부: UNIQUE 적용 필수.  
애플리케이션 검증 필요 여부: 필요.
