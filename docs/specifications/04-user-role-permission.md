## 설계 원칙

- 기본 거부와 최소 권한 원칙을 적용한다.
- 역할(RBAC) 검증 뒤 리소스 소유자·담당 부서(ABAC 성격)를 추가 검증한다.
- 직원의 부서 이동·겸직·임시 권한에는 유효기간과 승인자를 기록한다.
- 민감 조회는 목적과 사유를 요구하고 모두 감사로그로 남긴다.
- 관리자도 금융 원장 수정 권한은 갖지 않는다.

## 역할 연결 구조

- 직원과 역할은 MVP에서 `EMPLOYEE_ROLE` N:M 연결 테이블로 관리한다.
- 고객과 역할은 MVP에서 `CUSTOMER_ROLE` N:M 연결 테이블로 관리한다. 고객에게 허용되는 역할 범위는 별도로 검증한다.
- 역할과 세부 권한은 `ROLE_PERMISSION` N:M 연결 테이블로 관리한다.
- MVP 연결 테이블은 복합 PK로 중복 연결을 차단한다. `valid_from`/`valid_to` 기반 기간 권한은 향후 확장 TODO이다.
- 고객과 직원이 하나의 `USER_ACCOUNT`를 공유할지 별도 인증계정을 사용할지는 결정되지 않았다. 인증계정 구조를 확정하기 전까지 `CUSTOMER_ROLE`과 `EMPLOYEE_ROLE`은 업무 주체 기준 연결로 이해한다.
