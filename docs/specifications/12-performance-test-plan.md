# 성능 테스트 계획

## 기준 데이터

| 데이터 | 규모 |
|---|---:|
| 고객 | 100,000 |
| 신청 | 200,000 |
| 대출 | 100,000 |
| 금융거래 | 1,000,000+ |
| 감사로그 | 1,000,000+ |

분포는 균일하지 않게 구성해 실제와 유사한 상품 편중, 최근 기간 집중, 일부 다거래 고객과 연체 비율을 포함한다. 구체 분포는 TODO이다.

## 분석 대상

| 조회 | 주요 조건/정렬 | 검토 인덱스 |
|---|---|---|
| 고객별 신청 내역 | 고객번호, 신청일시 역순 | `(customer_id, received_at DESC)` |
| 고객별 대출 내역 | 고객, 실행일시 | 조인 경로 포함 TODO |
| 상품별 월간 신청 | 상품, 기간 | `(product_id, received_at)` |
| 처리기한 초과 신청 | 상태, 접수일 | `(status, received_at)` |
| 연체 대출 목록 | 연체 상태, 납부예정일 | `(status, due_date)` |
| 기간별 금융거래 | 대출번호, 거래일시 | `(loan_id, created_at)` |
| 직원별 개인정보 조회 | 직원번호, 조회일시 | `(employee_id, created_at)` |

## 개선 절차

```text
느린 쿼리 발견
→ EXPLAIN (ANALYZE, BUFFERS)
→ 병목 확인
→ 쿼리/인덱스 수정
→ 동일 데이터와 환경으로 재측정
→ 개선 전후 결과 기록
```

## 측정 항목

- p50/p95/p99 응답시간, 처리량과 오류율
- 실행계획, 실제/예상 행 수, buffer hit/read와 임시 파일
- CPU, 메모리, DB 연결 수, 락 대기와 디스크 I/O
- 인덱스 크기 및 INSERT/UPDATE 비용 변화

목표 응답시간, 동시 사용자, 워밍업·반복 횟수, 테스트 장비와 도구(k6/JMeter 등)는 TODO이다. 측정 결과는 실행계획과 원본 스크립트를 함께 보존하며 수치를 임의 작성하지 않는다.
