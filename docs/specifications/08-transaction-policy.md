# 트랜잭션 정책

## 기본 원칙

- 유스케이스 서비스의 public 메서드를 트랜잭션 경계로 삼는다.
- 쓰기 작업은 `@Transactional`, 단순 조회는 `@Transactional(readOnly = true)`를 기본으로 한다.
- 외부 API·파일 전송은 DB 트랜잭션 안에서 오래 대기하지 않는다. 원자적 후속 전파가 필요하면 Outbox 패턴을 검토한다.
- 예측 가능한 업무 오류와 시스템 오류의 롤백 규칙을 명시한다. checked exception 정책은 TODO이다.

## 대출 실행

```text
대출계약 생성
→ 실행 거래 기록
→ 신청 상태 변경
→ 상환계획 생성
→ 감사로그 기록
```

전체를 하나의 DB 트랜잭션으로 처리하며 한 단계라도 실패하면 전부 롤백한다. 신청 상태와 1:1 UNIQUE 제약을 함께 검사한다. 외부 지급 시스템 연동 시 단일 DB 트랜잭션만으로 원자성을 보장할 수 없으므로 상태 머신·Outbox·보상 절차를 별도 설계한다(TODO).

## 상환 처리

```text
상환 요청 및 멱등성 검증
→ 거래원장 기록
→ 현재 잔액 변경
→ 상환계획 반영
→ 필요 시 신청/대출 상태 변경
→ 감사로그 기록
```

원장과 잔액은 한 트랜잭션에서 변경한다. 원장은 삭제·수정하지 않고 정정 거래를 추가한다. 같은 멱등성 키와 같은 본문에는 최초 결과를 반환하고, 본문이 다르면 충돌로 거절한다.

## 동시성 제어

| 문제 | 1차 선택 | 대안/검토 |
|---|---|---|
| 동일 요청 중복 | UNIQUE 멱등성 키 | 처리 중 상태 및 결과 캐시 |
| 서로 다른 키의 동시 상환 | `LOAN.version` 낙관적 락 | 충돌 빈도가 높으면 행 비관적 락 |
| Lost Update | 조건부 UPDATE 또는 낙관적 락 | 원장 합계 기반 대사 |
| 동일 신청 중복 실행 | 신청 ID UNIQUE + 상태 검증 | 신청 행 잠금 |

PostgreSQL 기본 `READ COMMITTED`에서 시작하되 각 경쟁 조건 테스트 결과로 격리 수준을 결정한다. 전체 격리 수준을 무조건 높이지 않는다.

## 실패 처리

- DB 예외를 삼키지 않아 롤백을 보장한다.
- 실패 응답에 내부 SQL이나 개인정보를 노출하지 않는다.
- 재시도는 멱등성이 확보된 작업에만 제한적으로 적용한다.
- 트랜잭션 커밋 후 알림 실패는 핵심 거래를 되돌리지 않고 재처리 큐로 관리한다(TODO).
