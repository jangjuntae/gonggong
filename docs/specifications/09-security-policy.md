# 보안 정책

## 인증과 인가

- Spring Security를 사용하며 모든 업무 API는 기본 인증 필요로 설정한다.
- 역할 기반 접근통제 후 본인·담당 부서·담당 신청 여부를 리소스 수준에서 검증한다.
- 메서드 보안과 서비스 계층 검증을 병행해 URL 우회 접근을 방지한다.
- 세션 방식 또는 토큰 방식, MFA 적용 범위, 만료·재발급 정책은 TODO이다.
- 로그인 연속 실패 시 지연·잠금·알림 정책을 적용한다. 횟수와 해제 절차는 TODO이다.

## 자격정보와 개인정보

- 비밀번호는 검증된 적응형 해시(예: Argon2id 또는 bcrypt)와 개별 salt로 저장한다.
- 전화번호·계좌번호 등은 저장 시 암호화하고 키는 애플리케이션 설정과 분리한다.
- 검색이 필요한 값은 정규화된 별도 HMAC/해시 컬럼 사용을 검토한다.
- 화면·로그·예외·모니터링에 민감정보 원문을 출력하지 않는다.
- 개발·테스트에는 생성한 가상정보만 사용한다.

## 애플리케이션 보안

- JPA 바인딩과 Prepared Statement를 사용하고 동적 SQL의 식별자 화이트리스트를 적용한다.
- DTO 검증, 출력 인코딩, CSRF(세션 방식), CORS, 보안 헤더와 업로드 파일 검증을 적용한다.
- 토큰·세션 ID는 URL에 넣지 않고 TLS 전송, Secure/HttpOnly/SameSite 쿠키를 적용한다.
- 운영 비밀은 환경변수 직입력보다 Secret Manager 사용을 검토하며 저장소에 커밋하지 않는다.
- 의존성 및 컨테이너 취약점 점검 절차를 CI에 추가한다(TODO).

## 개인정보 조회 통제

조회 전 권한·부서·목적을 검증하고 조회 후 감사로그를 남긴다. 목록 API는 최소 필드만 반환하며 다운로드·대량 조회에는 별도 승인과 임계치 탐지를 적용한다.
