# 요구사항

상태는 `제안`, `확정`, `구현`, `검증`으로 관리한다. 현재 모든 항목은 `제안`이다.

## 기능 요구사항

| ID | 요구사항 | 완료 조건 |
|---|---|---|
| FR-001 | 회원 및 역할 관리 | 직원·고객에게 역할을 부여·회수하고 역할별 권한을 관리할 수 있다. 직원 역할과 권한 연결은 각각 `EMPLOYEE_ROLE`, `ROLE_PERMISSION`으로 보존한다. 고객 역할은 MVP에서 `CUSTOMER_ROLE`로 연결하며 공통 인증계정 도입 여부는 별도로 결정한다. |
| FR-002 | 정책금융 상품 관리 | 관리자가 상품의 기간·금리·한도를 관리한다. |
| FR-003 | 상품별 자격조건 관리 | 조건과 규칙 버전을 DB에서 관리한다. |
| FR-004 | 고객 신청 | 고객이 신청서를 임시저장하고 접수한다. |
| FR-005 | 증빙서류 등록 | 허용 형식·크기 검증 후 문서 메타데이터를 저장한다. |
| FR-006 | 자격검증 | 적용 규칙별 통과 여부와 미충족 사유를 제공한다. |
| FR-007 | 중복신청 확인 | 동일 상품 중복신청 정책에 따라 차단 또는 경고한다. |
| FR-008 | 담당자 배정 및 재배정 이력 | 신청을 담당 부서와 담당 직원에게 배정·해제할 수 있다. 현재 담당자를 한 명만 조회할 수 있어야 하며 배정일시, 배정자와 해제일시를 포함한 과거 재배정 이력을 보존한다. |
| FR-009 | 심사 | 담당자가 의견과 근거를 기록한다. |
| FR-010 | 보완 요청 | 보완 항목과 기한을 기록하고 고객에게 알린다. |
| FR-011 | 승인·거절 | 허용된 상태에서만 결과와 사유를 기록한다. |
| FR-012 | 대출 실행 | 승인 신청에 대해 계약·원장·상환계획을 원자적으로 생성한다. |
| FR-013 | 상환계획 생성 | 확정된 계산·반올림 정책으로 회차별 계획을 만든다. |
| FR-014 | 상환 처리 | 멱등성 키로 중복 반영 없이 원장과 잔액을 갱신한다. |
| FR-015 | 연체 관리 | 연체 일수·상태를 산정하고 대상 목록을 제공한다. |
| FR-016 | 감사로그 | 개인정보 조회와 중요 업무 행위를 변경 불가능한 이력으로 남긴다. |
| FR-017 | 이상거래 탐지 | 규칙과 판단 근거를 포함한 경보를 생성하고 관련 고객·신청·대출·금융거래를 명시적 FK로 연결한다. 경보에는 최소 하나 이상의 대상이 있어야 한다. |
| FR-018 | 운영 대시보드 | 개인정보를 노출하지 않는 집계 지표를 제공한다. |

## 비기능 요구사항

| ID | 요구사항 | 검증 기준 초안 |
|---|---|---|
| NFR-001 | 데이터 정합성 | PK/FK/UNIQUE/CHECK와 트랜잭션 테스트로 검증한다. |
| NFR-002 | 보안 | 인증, 인가, 입력 검증과 보안 테스트를 적용한다. |
| NFR-003 | 개인정보보호 | 최소 조회, 마스킹, 암호화와 접근 이력을 적용한다. |
| NFR-004 | 추적 가능성 | 주요 상태·심사·거래의 처리자와 전후 값을 추적한다. |
| NFR-005 | 성능 | 목표 응답시간과 동시 사용자 수는 부하 기준 확정 후 측정한다. |
| NFR-006 | 장애 복구 | 부분 실패 시 롤백하며 복구 절차를 문서화한다. |
| NFR-007 | 중복 요청 안전성 | 동일 키 요청은 한 번만 반영되고 같은 결과를 반환한다. |
| NFR-008 | 테스트 가능성 | 핵심 규칙을 외부 시스템 없이 자동 검증할 수 있다. |
